Overview

OriginSourceInstall

OSI is a source-first, local Linux package manager engineered to simplify compiling applications directly from source repositories while safeguarding system directories. By compiling directly from verified source directories instead of running opaque binary releases, OSI allows developers and power-users to audit, adjust, and deploy builds.

Auditable Safe Builds

Review and compile applications using lightweight, plain text .instruct recipes. No binary mystery boxes.

Cross-Distribution Compatibility

Automatic platform detection abstracts package execution on Debian/Ubuntu, RedHat/Fedora, and Arch Linux.

Deployment

Installation Methods

Deploy OSI as a global system executable or configure it inside your isolated user directory workspace.

Downloads the binary manager to /usr/local/bin/osi. Available to all terminal sessions.

BASH COMMAND 
sudo curl -fsSL "https://raw.githubusercontent.com/AstroMeYT/OSI/refs/heads/main/osi.sh" -o /usr/local/bin/osi && sudo chmod +x /usr/local/bin/osi

Installs within your home folder workspace. Ensure ~/.local/bin is loaded inside your terminal's environmental $PATH variables.

BASH COMMAND 
mkdir -p ~/.local/bin && curl -fsSL "https://raw.githubusercontent.com/AstroMeYT/OSI/refs/heads/main/osi.sh" -o ~/.local/bin/osi && chmod +x ~/.local/bin/osi
Manual

CLI Commands

Interact with OSI using direct terminal subcommands. The manager references local cache structures, performing searches and automated dependency alignment:

osi search <query>
Queries the packages SQLite index for keywords in name, author, or description.
osi search ollama
osi install <pack-name>
Fetches matching instruction files, builds prerequisites, compiles targets, and logs setup locations.
osi install ollama
osi remove <pack-name>
Parses registered file directories and cleans up build folders and execution pathways.
osi remove ollama
osi list
Pulls a structured catalog of active installations managed and tracked by the local database.
osi list
Resolution

Dependencies & Integration

Compiling source targets requires reliable build dependencies. During runtime execution, OSI dynamically handles dependencies step-by-step:

Resolution Strategy
  1. Platform Analysis: Verifies host distribution files via /etc/os-release to locate the native binary manager (apt-get, dnf, or pacman).
  2. Utility Managers: If dedicated compilation layers (such as cargo, npm, or pip) are required, the manager prompts to install them automatically.
  3. System Libraries: Parses developer requirements and prompts the user for authorization before performing installation steps.
Configuration

Writing .instruct Files

Applications inside the OSI indexing system are defined via plain text .instruct packages. These files contain configuration meta header blocks, followed by plain execution steps:

Header Tag Type Constraint Operational Description
app-name String (Lowercase) The target identifier registered in system database directories.
author String Identifies publishers, organizations, or individual maintainers.
git-url HTTPS Git Address / None The repository location cloned into transient build directory structures.
supported-system-base debian, redhat, arch, all Ensures build rules are restricted to compatible environments.
required-pms system, cargo, npm, pip Checks and provisions high-level runtime build dependencies.
required-dependencies Comma-separated strings Core system utilities and libraries requested prior to building.
allow-clone-deletion true / false Prunes source trees upon successful build to preserve disk space.

Below these configuration values, write step-by-step build commands. The terminal script sequence must end with the [exit] token.

OLLAMA.INSTRUCT 
app-name = ollama
author = Ollama
git-url = https://github.com/ollama/ollama
supported-system-base = debian, redhat
required-pms = system
required-dependencies = dependencies
allow-clone-deletion = true
curl -fsSL https://ollama.com/install.sh | sh
[exit]
Core Storage

Repository Index Schema

OSI uses an index database format managed via SQLite. This local file is updated directly during sync cycles. The underlying schema is verified as follows:

SQL SCHEMA DEFINITION 
CREATE TABLE IF NOT EXISTS packages (
    id INTEGER PRIMARY KEY AUTOINCREMENT, 
    name TEXT UNIQUE, 
    author TEXT, 
    git_url TEXT, 
    instruct_url TEXT, 
    description TEXT
);
Tooling

Database Management UI

Maintainers can use the companion Python utility dbman.py to manage packages. It allows developers to add, edit, or delete registry profiles without writing raw database transactions.

Metadata Editor

Provides fields to update author, Git source tree URLs, and direct raw raw URL paths for .instruct files.

Incremental Filter

Instantly search locally cached package keys while performing maintenance tasks.

GitHub Synchronization Workflow

To sync modifications with downstream OSI clients, commit and push changes back to the origin Git tree: 

git add packages.db
git commit -m "Update package register index"
git push origin main
